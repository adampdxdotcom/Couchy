Folder: src/api

File: src/api/client.ts
Purpose:
  Centralized, typed frontend HTTP API client (`api` object) wrapping `fetch`
  calls to the Express backend (`/api/*`). Provides `requestJson` error handling
  and exposes domain-grouped methods for:
  - System & Scans: health/status checks, runtime config updates, scan
    triggers, and scan job history.
  - Organization & Gallery: metadata/tags/collections/saved-search presets,
    filtered image queries, image details, single/bulk image annotations, and
    ZIP archive downloads.
  - Characters: character CRUD, character merging, linking/unlinking LoRAs and
    workflows, single/bulk character-image association status updates, and
    running suggestion heuristics.
  - LoRAs, Models & Workflows: LoRA explorer listing/classification/@mention
    configuration, model inventory listing/syncing, model usage impact reports,
    Civitai and Hugging Face searches, confirmed model downloads, workflow CRUD,
    and setting the default workflow.
  - ComfyUI & Reproduction: connection testing, live queue/progress polling,
    workflow reproduction validation/submission, and reproduction job history.
  - Backups: database backup listing/creation and annotation JSON restores.
  - Generation Studio: prompt template CRUD, workflow node mapping retrieval
    and saving, LM Studio status/config/guiding templates/prompt-set generation,
    image interrogation, batch submission, and generation batch history.
  - Visual Keyword Tagger (WD14 ONNX): tagger status/config updates, queue
    control actions, and per-image visual tag rescanning or removal.

File: src/server/services/characterService.ts
Responsible for:
  Character profile builder, merge engine, and deterministic Assisted Character
  Identification engine. Aggregates character portraits (honoring explicit user
  selections before fallback), aliases, LoRAs, workflows, tags, collections, and
  gallery statistics; executes transactional character merges; runs heuristic
  matching across linked LoRAs (0.90), prompt name/alias regexes (0.75), and
  linked workflows (0.65) for single images or the whole gallery without
  overwriting confirmed/rejected matches; and updates LoRA categories.

File: src/server/services/comfyuiLiveMonitor.ts
Responsible for:
  Real-time ComfyUI queue and WebSocket execution monitor. Maintains a live
  WebSocket connection to ComfyUI `/ws` (capturing step progress, active node,
  and prompt completion/error transitions) combined with cached `/queue` HTTP
  polling, and assembles active/queued/indexing ghost preview cards from
  `generation_items`, `reproduction_jobs`, and external direct ComfyUI queue
  entries.

File: src/server/services/comfyuiService.ts
Responsible for:
  ComfyUI integration, model inventory synchronization, and workflow reproduction
  service. Tests ComfyUI `/system_stats` connectivity, recursively scans local
  model folders and ComfyUI `/object_info` to compute SHA-256/AutoV2 hashes and
  sync the `models` inventory, converts standard visual workflows to API prompt
  graphs, validates reproduction readiness (checking missing models/custom nodes
  without silent substitution), injects edited positive prompts, dispatches
  reproduction jobs to `/prompt`, and polls `/history` to index outputs.

File: src/server/services/galleryQueryService.ts
Responsible for:
  High-performance gallery query, hydration, and boolean search engine. Batch-
  hydrates `ImageRecord` objects without N+1 queries or heavy JSON blobs,
  evaluates complex boolean search expressions (`AND`, `OR`, `NOT`, `field:value`,
  numeric comparisons, quoted phrases, and universal word matching across
  prompts/tags/LoRAs/characters/visual tags), applies multi-LoRA/character/
  status/date filters and 9 sort modes, and aggregates LoRA Explorer records.

File: src/server/services/lmStudioService.ts
Responsible for:
  LM Studio OpenAI-compatible LLM/VLM integration and prompt interrogation
  pipeline. Manages SQLite-persisted LM Studio settings and Guiding Prompt
  Templates, checks `/v1/models` availability, generates themed multi-shot photo
  set prompts (with sanitization and an offline fallback shot director), and
  runs a hybrid image-to-prompt pipeline (Vision-Language Model direct captioning
  with automatic fallback to local WD14 ONNX tag extraction + text LLM
  synthesis, stripping physical character identity traits when a character LoRA
  is active).

File: src/server/services/modelManagerService.ts
Responsible for:
  External model discovery and verified download manager. Queries Civitai
  (by AutoV2/SHA-256 hash or text search) and Hugging Face Hub APIs to resolve
  downloadable `.safetensors`/checkpoint/LoRA files, validates target filenames
  against path traversal and overwrite rules, streams confirmed downloads to
  `.part` files in `DOWNLOADS_DIR` with live progress tracking in `download_jobs`,
  verifies SHA-256 checksums, registers downloaded models, and syncs inventory.

File: src/server/services/pngMetadataParser.ts
Responsible for:
  Read-only PNG binary chunk (`tEXt`, `iTXt`, `zTXt`) and generation metadata
  extractor. Parses ComfyUI API graphs (`prompt` chunk), ComfyUI visual workflows
  (`workflow` chunk), and Automatic1111 `parameters` text chunks; traces upstream
  conditioning, switches, and `StringConcatenate` nodes to extract positive/
  negative prompts, seeds, sampler settings, checkpoints, VAEs, ControlNets,
  CLIPs, upscalers, and single/multi-slot LoRAs with provenance tracking.

File: src/server/services/scannerService.ts
Responsible for:
  Filesystem image indexer, thumbnail generator, and live directory watcher.

  across file moves), generates 384px WebP thumbnails via `sharp` (plus a
  non-blocking startup migration), extracts and persists metadata/workflows/
  LoRAs/dependencies, reconciles missing files, links completed generation items
  by seed, and triggers assisted character ID and visual tagging.

File: src/server/services/visualTaggerService.ts
Responsible for:

  database inference (supporting CPU or CUDA execution), non-blocking
  background queue processing with pause/resume/rescan controls, and per-image
  visual tag storage and removal.

File: src/server/services/workflowMapperService.ts
Responsible for:
  Workflow node-mapping and generation-time API graph compiler. Computes target

  Node.js package manifest defining scripts (`dev` and `start` running
  `tsx server.ts`, `build` running `vite build`, `preview`, `clean`, and `lint`
  running `tsc --noEmit`) along with runtime and development dependencies
  (Express, `better-sqlite3`, `sharp`, `onnxruntime-node`, `chokidar`, `archiver`,
  React 19, Vite, Tailwind CSS v4, Lucide icons, Motion, and TypeScript).

File: server.ts
Responsible for:
  Main full-stack application server entry point. Runs SQLite migrations and
  one-time prompt backfill, starts the `chokidar` filesystem watcher, initializes
  Express (`25mb` JSON payload limit), mounts all `/api/*` routers, schedules
  5-minute directory reconciliation scans, mounts Vite dev middleware (or serves
  static `dist/` in production), listens on `0.0.0.0:<port>`, and triggers
  non-blocking startup tasks (384px WebP thumbnail migration, model inventory
  sync, incremental image scan, and visual tagger queue resume).

File: tsconfig.json
Responsible for:
  TypeScript compiler configuration targeting `ES2022` / `ESNext` with bundler
  module resolution, `react-jsx`, `@/*` path alias to the workspace root, and
  `noEmit: true` for typechecking (`npm run lint`).

File: vite.config.ts
Responsible for:
  Vite bundler configuration enabling `@vitejs/plugin-react` and
  `@tailwindcss/vite`, configuring the `@` path alias to the project root, and
  toggling HMR/file-watching based on `DISABLE_HMR`.
